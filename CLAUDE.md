# MacDivvun.service

macOS background `NSApplication` (`LSBackgroundOnly`, `LSUIElement`) that hosts an `NSSpellServer`. Installed at `/Library/Services/MacDivvun.service`. At launch it scans `~/Library/Services` and `/Library/Services` for `<locale>.bundle/Contents/Resources/*.drb`, loads each `.drb` via the bundled `libdivvun_runtime.a`, creates a pipeline, and registers the bundle dirname (`sma.bundle` → `sma`) with `NSSpellServer.registerLanguage(_:byVendor:)` under vendor `"MacDivvun"`. An `FSEventStream` watches the same directories so new bundles get loaded without a restart.

## Build / develop

```sh
sh ./scripts/build.sh          # produces unsigned ./MacDivvun.service
```

In Xcode:

```sh
Vendor/pkgconfig/generate.sh   # writes Vendor/pkgconfig/divvun-runtime.pc
xcodegen generate              # writes MacDivvun.xcodeproj
open MacDivvun.xcodeproj
```

The Xcode project is generated from `project.yml`; it's not committed.

Signing, notarization, and `.pkg`/installer packaging happen in a separate, external pipeline. Nothing in this repo signs.

## Architecture

All Swift under `Sources/`:

- `main.swift` — `NSApplicationMain` entry point. The custom NSApplication class is wired via `Info.plist` `NSPrincipalClass = MacDivvun.MacDivvunRunner`.
- `MacDivvunApp.swift` — `MacDivvunRunner` (NSApplication) + `AppDelegate`. Sets up `os.Logger` and Sentry, builds the registry, scans bundle dirs, starts `BundlesWatcher`, calls `server.run()`.
- `SpellerRegistry.swift` — `actor` keyed by locale, owns `[locale: PipelineHandle]` plus correctness + suggestion caches. Exposes `register(bundleAt:)`, `isCorrect`, `suggestions`, `firstMisspelling`. Locale derived from `<locale>.bundle` dirname; no `.drb` introspection.
- `SpellServerDelegate.swift` — `NSSpellServerDelegate` impl. Bridges the sync NSSpellServer callbacks to the async registry via a small semaphore shim. UTF-8 byte index from the pipeline → `NSRange` via `String.Index` arithmetic with safe `samePosition(in:)`.
- `BundlesWatcher.swift` — `FSEventStream` wrapper. Uses `Unmanaged.passRetained` + an explicit `release` callback in the context — survives ownership refactors, unlike the old codebase.
- `DivvunRuntime.swift` — Swift wrapper around the `libdivvun_runtime` C FFI. Originally vendored from `divvun-runtime/bindings/swift/`, then restructured (no per-call closures capturing mutable state; serialized global error slot + top-level `@_cdecl` callback). The same restructured file has been mirrored back upstream.

C symbols come in through `Sources/MacDivvun-Bridging-Header.h` → `Vendor/divvun_runtime.h`.

## Dependencies

- **DivvunRuntime** — vendored into `Sources/DivvunRuntime.swift`. Static-linked from `Vendor/libdivvun_runtime.a` via pkg-config glue (`Vendor/pkgconfig/divvun-runtime.pc.in` → `divvun-runtime.pc` generated by `generate.sh`). `OTHER_LDFLAGS` in `project.yml` adds the `.a` and the required Apple frameworks (CoreML, Accelerate, plus sqlite3/iconv/c++).
- **Sentry** (SPM, github.com/getsentry/sentry-cocoa, 8.x). DSN read from `Info.plist`'s `SENTRY_DSN`; init is in `AppDelegate.startSentry()`.

No CocoaPods. No `.xcworkspace`. No Fastlane.

## Speller bundle layout (what this service consumes)

Bundles are placed in `~/Library/Services` (user) or `/Library/Services` (system) by some external installer. Each is:

```
<locale>.bundle/
└── Contents/Resources/<locale>.drb
```

Locale registration is dirname-only. If a locale loads twice (e.g. user override of a system bundle), the first wins.

## Gotchas — read before editing

1. **Vendored `DivvunRuntime.swift` instead of SPM.** Upstream `bindings/swift/include/divvun_runtime.h` is a broken symlink (committed: points at `../c/...`, should be `../../c/...`). When that's fixed in divvun-runtime, drop the vendored file and add the package via SPM. The Swift source has been mirrored upstream, so once the symlink is repaired the two will match.
2. **Swift 6.3.2 SendNonSendable bug.** The original DivvunRuntime wrapper used per-call closures capturing a mutable `ErrorCapture` class; Swift 6.3.2's region-analysis pass crashes (not errors — segfaults) on that pattern when called from C function pointer types. The current shape (`runFFI` + serialized global + `@_cdecl` callback) avoids it. Don't reintroduce per-call closures with captured mutable state inside this file.
3. **`forward` errors come through the callback, not a nil return.** `DRT_PipelineHandle_forward` returns a `rust_slice_t` directly (not Optional), so the only failure signal is the C callback firing. `forward` reads `drtLastError` under the lock after the call — don't remove that path "to silence a warning".
4. **`MacDivvun.xcodeproj` is generated.** Don't edit the project in Xcode and expect it to stick — edit `project.yml` and run `xcodegen generate`. The project dir is gitignored.
5. **`libdivvun_runtime.a` must exist before building.** Symlinked to `divvun-runtime/target/release/libdivvun_runtime.a` for dev. `scripts/build.sh` errors out cleanly if missing.

## Conventions for Claude

- Swift naming (`camelCase` methods, `UpperCamelCase` types).
- Delete code rather than commenting it out or marking it deprecated. Don't leave "removed X" breadcrumbs.
- Don't write decorative comments. Only comment when the *why* is non-obvious.
- Don't add features the task doesn't require.
